# MySQL to PostgreSQL Converter - Feature Reference

This document describes the MySQL syntax and features that the converter handles,
along with known limitations.

## Supported Features

### Data Types

| MySQL Type | PostgreSQL Type | Notes |
|------------|-----------------|-------|
| `TINYINT` | `SMALLINT` | PostgreSQL has no 1-byte integer |
| `SMALLINT` | `SMALLINT` | Direct mapping |
| `MEDIUMINT` | `INTEGER` | PostgreSQL has no 3-byte integer |
| `INT` / `INTEGER` | `INTEGER` | Size specifiers removed |
| `BIGINT` | `BIGINT` | Direct mapping |
| `FLOAT` | `REAL` | Via sqlglot |
| `DOUBLE` | `DOUBLE PRECISION` | Via sqlglot |
| `DECIMAL` / `NUMERIC` | `NUMERIC` | Precision preserved |
| `CHAR(n)` | `VARCHAR(n)` | Avoids PostgreSQL CHAR padding |
| `VARCHAR(n)` | `VARCHAR(n)` | Direct mapping |
| `TINYTEXT` | `TEXT` | PostgreSQL TEXT is unlimited |
| `TEXT` | `TEXT` | Direct mapping |
| `MEDIUMTEXT` | `TEXT` | PostgreSQL TEXT is unlimited |
| `LONGTEXT` | `TEXT` | PostgreSQL TEXT is unlimited |
| `BINARY(n)` | `BYTEA` | Size removed |
| `VARBINARY(n)` | `BYTEA` | Size removed |
| `TINYBLOB` | `BYTEA` | Direct mapping |
| `BLOB` | `BYTEA` | Direct mapping |
| `MEDIUMBLOB` | `BYTEA` | Direct mapping |
| `LONGBLOB` | `BYTEA` | Direct mapping |
| `DATETIME` | `TIMESTAMP` | Via sqlglot |
| `TIMESTAMP` | `TIMESTAMP` | Direct mapping |
| `DATE` | `DATE` | Direct mapping |
| `TIME` | `TIME` | Direct mapping |
| `YEAR` | `SMALLINT` | PostgreSQL has no YEAR type |
| `ENUM(...)` | `TEXT` | PostgreSQL ENUM requires CREATE TYPE |
| `SET(...)` | `TEXT` | No PostgreSQL equivalent |
| `JSON` | `JSONB` | Binary JSON for better performance |

### Unsigned Integer Handling

MySQL unsigned integers are converted to the next larger signed type or handled
specially:

| MySQL Type | PostgreSQL Type |
|------------|-----------------|
| `TINYINT UNSIGNED` | `SMALLINT` |
| `SMALLINT UNSIGNED` | `INTEGER` |
| `MEDIUMINT UNSIGNED` | `INTEGER` |
| `INT UNSIGNED` | `BIGINT` |
| `BIGINT UNSIGNED` | `BIGINT` (with overflow handling) |

Unsigned overflow values are converted:
- `4294967295` (UINT_MAX) → `-1`
- `18446744073709551615` (UINT64_MAX) → `-1`

### AUTO_INCREMENT

MySQL `AUTO_INCREMENT` is converted to PostgreSQL `GENERATED BY DEFAULT AS IDENTITY`:

```sql
-- MySQL
CREATE TABLE t (id INT AUTO_INCREMENT PRIMARY KEY);

-- PostgreSQL
CREATE TABLE t (id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY);
```

### DDL Statements

#### CREATE TABLE

- Table structure fully converted via sqlglot
- Table options removed: `ENGINE`, `CHARSET`, `COLLATE`, `ROW_FORMAT`, `COMMENT`
- Index definitions extracted (inline `KEY`/`INDEX` removed)
- `AUTO_INCREMENT` converted to `IDENTITY`
- Column `COMMENT` clauses removed
- `ON UPDATE CURRENT_TIMESTAMP` removed (requires trigger in PostgreSQL)

#### ALTER TABLE

| MySQL Syntax | PostgreSQL Conversion |
|--------------|----------------------|
| `ADD COLUMN col type` | `ADD COLUMN col type` |
| `ADD COLUMN col type AUTO_INCREMENT` | `ADD COLUMN col type GENERATED BY DEFAULT AS IDENTITY` |
| `DROP col` | `DROP COLUMN col` |
| `DROP COLUMN col` | `DROP COLUMN col` |
| `DROP PRIMARY KEY` | `DROP CONSTRAINT tablename_pkey` |
| `DROP KEY idx` | `DROP INDEX IF EXISTS idx` |
| `DROP INDEX idx` | `DROP INDEX IF EXISTS idx` |
| `MODIFY COLUMN col type` | `ALTER COLUMN col TYPE type` |
| `CHANGE old new type` | `RENAME COLUMN old TO new; ALTER COLUMN new TYPE type` |
| `CHANGE col col type AUTO_INCREMENT` | `ALTER COLUMN col TYPE type; ALTER COLUMN col ADD GENERATED BY DEFAULT AS IDENTITY` |
| `ADD INDEX idx (cols)` | `CREATE INDEX IF NOT EXISTS idx ON table (cols)` |
| `ADD KEY idx (cols)` | `CREATE INDEX IF NOT EXISTS idx ON table (cols)` |
| `ADD UNIQUE INDEX idx (cols)` | `CREATE UNIQUE INDEX IF NOT EXISTS idx ON table (cols)` |
| `RENAME TABLE old TO new` | `ALTER TABLE old RENAME TO new` |
| `CONVERT TO CHARACTER SET` | Removed (comment added) |

Column positioning clauses are removed:
- `AFTER column_name`
- `FIRST`

#### DROP TABLE / TRUNCATE

Converted directly via sqlglot.

### DML Statements

#### INSERT

- `INSERT INTO` converted directly
- `REPLACE INTO` converted to `INSERT INTO`
- `ON DUPLICATE KEY UPDATE` converted to `ON CONFLICT DO UPDATE SET`

#### UPDATE

- Basic `UPDATE` statements converted directly
- `UPDATE ... LIMIT n` - LIMIT clause removed
- `UPDATE ... ORDER BY` - Converted to PL/pgSQL DO block with cursor

#### DELETE

- Basic `DELETE` statements converted directly
- `DELETE ... LIMIT n` - LIMIT clause removed

### Literals and Values

#### Hex Literals

MySQL hex literals are converted to decimal integers:

```sql
-- MySQL
INSERT INTO t VALUES (0xDEADBEEF);

-- PostgreSQL
INSERT INTO t VALUES (3735928559);
```

Hex literals inside string literals are preserved unchanged.

#### BYTEA Column Hex Literals

For columns storing binary data (BYTEA), hex literals are converted to
PostgreSQL's `decode()` function instead of integers:

```sql
-- MySQL
INSERT INTO build_auth_key (build, key) VALUES (12340, 0x66FC5E09AB...);

-- PostgreSQL
INSERT INTO build_auth_key (build, key) VALUES (12340, decode('66FC5E09AB...', 'hex'));
```

The converter automatically detects BYTEA columns in these tables:

| Table | Columns |
|-------|---------|
| `build_auth_key` | `key` |
| `build_executable_hash` | `executablehash` |
| `warden_checks` | `data`, `result` |

Additional tables can be configured in `config/bytea_tables.py`.

#### String Escapes

| MySQL | PostgreSQL |
|-------|------------|
| `\'` | `''` |
| `\\` | `\\` |
| `\"` in double-quoted strings | Converted to single-quoted |

Double-quoted strings are converted to single-quoted (PostgreSQL uses double
quotes for identifiers).

#### Character Set Introducers

MySQL character set introducers are removed:

```sql
-- MySQL
_utf8'string'

-- PostgreSQL
'string'
```

### Identifiers

#### Backticks

MySQL backtick-quoted identifiers are converted:

```sql
-- MySQL
SELECT `column` FROM `table`;

-- PostgreSQL
SELECT column FROM table;
```

Reserved keywords are preserved with double quotes:

```sql
-- MySQL
SELECT `key`, `type` FROM `table`;

-- PostgreSQL
SELECT "key", "type" FROM table;
```

#### Case Sensitivity

All identifiers are lowercased to match PostgreSQL's default behavior.

### Operators

| MySQL | PostgreSQL | Notes |
|-------|------------|-------|
| `&~n` | `& ~n` | Bitwise AND NOT (space required) |
| `col & n` (in WHERE) | `(col & n) <> 0` | Explicit boolean comparison |

### Functions

Common function conversions applied automatically:

| MySQL Function | PostgreSQL Equivalent |
|----------------|----------------------|
| `IFNULL(a, b)` | `COALESCE(a, b)` |
| `UNIX_TIMESTAMP()` | `EXTRACT(EPOCH FROM NOW())` |
| `FROM_UNIXTIME(n)` | `TO_TIMESTAMP(n)` |

The converter includes a function mapping registry in
`config/function_mappings.py` that defines conversions for:

- **Date/Time**: `NOW()`, `CURDATE()`, `CURTIME()`, `DATE_FORMAT()`,
  `STR_TO_DATE()`, `DATEDIFF()`, `DATE_ADD()`, `DATE_SUB()`
- **String**: `CONCAT()`, `CONCAT_WS()`, `LENGTH()`, `SUBSTRING()`, `TRIM()`,
  `UPPER()`, `LOWER()`, `REPLACE()`, `LPAD()`, `RPAD()`, `INSTR()`, `LOCATE()`
- **Numeric**: `ABS()`, `CEIL()`, `FLOOR()`, `ROUND()`, `TRUNCATE()` → `TRUNC()`,
  `MOD()`, `RAND()` → `RANDOM()`, `GREATEST()`, `LEAST()`
- **Conditional**: `IF()` → `CASE WHEN`, `IFNULL()` → `COALESCE()`, `NULLIF()`,
  `ISNULL()` → `IS NULL`
- **Aggregate**: `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`,
  `GROUP_CONCAT()` → `STRING_AGG()`
- **Type Conversion**: `CAST()`, `CONVERT()` → `CAST()`

### MySQL-Specific Artifacts Removed

The converter removes mysqldump artifacts:

- `/*!40101 SET ... */` conditional comments
- `SET NAMES utf8`
- `SET character_set_client`
- `SET @OLD_...` variable assignments
- `LOCK TABLES` / `UNLOCK TABLES`
- `SET FOREIGN_KEY_CHECKS`
- `SET UNIQUE_CHECKS`
- `SET SQL_MODE`

### User Variables

MySQL user variables are expanded inline:

```sql
-- MySQL
SET @GUID := 1000;
INSERT INTO t VALUES (@GUID);

-- PostgreSQL
INSERT INTO t VALUES (1000);
```

### VIEW Definitions

MySQL VIEW definitions inside conditional comments are extracted and converted
to PostgreSQL CREATE VIEW statements.

## Appendix A: Unsupported Features

The following MySQL features require manual conversion and will trigger fallback
warnings.

### Multi-Clause ALTER TABLE with Multiple CHANGE

When an ALTER TABLE contains multiple CHANGE clauses, only the first is
converted:

```sql
-- MySQL (not fully supported)
ALTER TABLE t
  CHANGE col1 col1 INT NOT NULL,
  CHANGE col2 col2 VARCHAR(50),
  CHANGE col3 col3 BIGINT;
```

**Workaround**: Split into separate statements:

```sql
ALTER TABLE t ALTER COLUMN col1 TYPE INTEGER;
ALTER TABLE t ALTER COLUMN col2 TYPE VARCHAR(50);
ALTER TABLE t ALTER COLUMN col3 TYPE BIGINT;
```

### DELIMITER and Stored Procedures

MySQL stored procedures use DELIMITER to allow semicolons inside procedure
bodies:

```sql
-- MySQL (not supported)
DELIMITER ||
CREATE FUNCTION my_func() RETURNS INT
BEGIN
  RETURN 1;
END||
DELIMITER ;
```

**Workaround**: Rewrite using PostgreSQL PL/pgSQL syntax:

```sql
CREATE FUNCTION my_func() RETURNS INTEGER AS $$
BEGIN
  RETURN 1;
END;
$$ LANGUAGE plpgsql;
```

### MySQL-Specific String Functions

| MySQL Function | Status | PostgreSQL Alternative |
|----------------|--------|------------------------|
| `SUBSTRING_INDEX(str, delim, count)` | Not supported | Use `split_part()` or regexp |
| `GROUP_CONCAT(...)` | Not supported | Use `string_agg()` |
| `FIND_IN_SET(str, strlist)` | Not supported | Use `= ANY(string_to_array())` |

### Complex PRIMARY KEY Operations

Combining DROP PRIMARY KEY and ADD PRIMARY KEY in one statement may fail:

```sql
-- MySQL (may fail)
ALTER TABLE t
  DROP PRIMARY KEY,
  ADD PRIMARY KEY (new_col);
```

**Workaround**: Split into separate statements:

```sql
ALTER TABLE t DROP CONSTRAINT t_pkey;
ALTER TABLE t ADD PRIMARY KEY (new_col);
```

### INSERT ... SELECT with AUTO_INCREMENT

PostgreSQL IDENTITY columns don't auto-generate values when explicitly
inserting:

```sql
-- May need OVERRIDING SYSTEM VALUE
INSERT INTO t (id, name) SELECT id, name FROM other_table;
```

### Spatial Data Types

MySQL spatial types (`GEOMETRY`, `POINT`, `POLYGON`, etc.) require PostGIS
extension and are not automatically converted.

### Full-Text Search

MySQL `FULLTEXT` indexes are removed. PostgreSQL uses different full-text
search syntax with `tsvector` and `tsquery`.

## Appendix C: Conversion Pipeline

The converter uses a four-stage pipeline:

1. **Preprocessing**: Remove mysqldump artifacts, extract VIEWs, expand user
   variables
2. **Splitting**: Split SQL into individual statements
3. **Transformation**: Route statements to DDL or DML converters
   - DDL uses sqlglot with pre/post processing
   - DML uses regex-based conversion
4. **Postprocessing**: Final cleanup, lowercase identifiers, append VIEWs

### DDL Processing Flow

```
MySQL DDL
    ↓
remove_backticks()
    ↓
remove table options (ROW_FORMAT, ENGINE, etc.)
    ↓
convert ALTER TABLE operations
    ↓
sqlglot.transpile(read="mysql", write="postgres")
    ↓
postprocess types (UTINYINT → SMALLINT, etc.)
    ↓
PostgreSQL DDL
```

### DML Processing Flow

```
MySQL DML
    ↓
remove_backticks()
    ↓
convert double-quoted strings to single-quoted
    ↓
convert escape sequences (\' → '')
    ↓
convert hex literals (0xABC → 2748)
    ↓
convert operators (&~ → & ~)
    ↓
convert functions (IFNULL → COALESCE)
    ↓
convert statements (REPLACE INTO → INSERT INTO)
    ↓
PostgreSQL DML
```
